# ADR 0007: Читання зовнішніх статусів тривог

- Статус: Proposed
- Дата: 2026-11-05

## Контекст

Оператору потрібні актуальні зовнішні відомості для Полтавської області й Кременчуцької громади. Джерела мають різне покриття: alerts.in.ua надає статуси за UID області `19` і громади `1088`; NEPTUN надає області та райони, але не громади. Помилка, обмеження частоти або застаріла відповідь не доводять, що тривоги немає.

## Рішення

Watcher читає джерела через серверний endpoint `GET /api/v1/alert-sources/status`. Токен alerts.in.ua зберігається тільки в конфігурації сервера (`ALERTS_IN_UA_TOKEN` або `AlertSources:AlertsInUa:Token`) і надсилається як Bearer. Клієнт не отримує токен і не звертається безпосередньо до API постачальника.

Статус нормалізується окремо для області, району й громади. NEPTUN зіставляється за стабільними ключами `poltavska` й `poltavska:kremenchutskyi`; ключ визначає географічну сутність незалежно від її підпису. Відомий підпис із невідомим ключем вважається зміною контракту й дає `unknown`. Дані для району не підміняють статус громади. Відповідь зберігає стан, рівень (червоний/жовтий, якщо джерело його повідомило), джерело, охоплення, час перевірки, час даних за наявності, свіжість і останній відомий стан. `partial`, `unknown`, `stale` та `conflict` не перетворюються на `inactive`. Код `N` alerts.in.ua консервативно мапиться в `unknown`, оскільки документація конкретного endpoint визначає його як відсутність інформації. Записи з повтореним ключем або невідомою структурою NEPTUN дають `unknown`. Поле NEPTUN `since` позначає початок тривоги, а не оновлення даних, тому API його не видає як `dataUpdatedAtUtc`.

Якщо свіже основне спостереження alerts.in.ua суперечить NEPTUN, оператор бачить `conflict`, а `authoritativeObservation` зберігає вибране основне спостереження. NEPTUN використовується як резервне спостереження для області, коли свіже основне спостереження недоступне. Жодне спостереження цього модуля саме собою не створює команду оповіщення.

Інтерфейс показує атрибуцію поруч із кожним спостереженням і посилається на [alerts.in.ua](https://alerts.in.ua/) та [NEPTUN](https://neptun.in.ua/). Статус оновлюється окремим same-origin запитом; кеш браузера для API вимкнений.

## Наслідки

- Ключ джерела налаштовується лише на сервері; його значення не виводиться у відповідь або журнал.
- Обробники джерел мають часові обмеження й інтервали опитування, що вкладаються у їхні ліміти.
- Неочікувана помилка одного провайдера журналюється без повідомлення винятку й перетворюється на невідоме спостереження; інше джерело продовжує відповідь.
- Кеш і блокування опитування локальні для процесу. Поки не додано спільну координацію частоти між репліками, застосунок із джерелами працює в одній репліці.
- Відповідь кожного джерела є незалежним спостереженням; розбіжність видима оператору й не змінює пріоритет основного джерела.
- Автоматичне створення команди, правила підтвердження й відбою належать до окремого рішення та модуля.
- Сервіси джерел реєструються розширенням `AddAlertSources` у `Program.cs`.

### Потік NEPTUN

Для розгортання з одним екземпляром доступний окремий необов’язковий адаптер `AddNeptunRealtimeMonitor`. Його потрібно підключати після `AddAlertSources`; базове розширення джерел не запускає довготривале з’єднання автоматично. Адаптер відкриває один WSS-зв’язок із фіксованим хостом `neptun.in.ua`, а REST `GET /api/v1/alerts` використовується для початкового стану й резервного відновлення. REST-відповідь обмежена 1 МіБ, зокрема коли сервер не передає `Content-Length`. До окремого узгодженого кроку адаптер не підключається в `Program.cs`.

Лише валідний envelope `alerts` атомарно замінює повний набір статусів області та району. `snapshot` містить дані про загрози, тому не змінює стан тривог; heartbeat лише підтверджує активність з’єднання. Некоректний envelope скидає актуальне спостереження до `unknown`; розрив або відсутність heartbeat протягом двох хвилин позначає останній відомий стан як застарілий. Після цього виконується REST fallback, якщо попередня спроба була щонайменше 15 секунд тому, а повторне підключення використовує обмежену експоненційну затримку. Порожні валідні списки в `alerts`/REST означають `inactive`; неповний чи невідомий формат — ні.

Адаптер зіставляє `poltavska` та `poltavska:kremenchutskyi`. NEPTUN район не є статусом громади й не може підміняти її. Він не додає окремого `IAlertSourceProvider`, тому не дублює NEPTUN-спостереження в одній відповіді. Стан потоку й кеш агрегатора локальні для процесу; leader election і спільного сховища немає. Увімкнений адаптер дозволено запускати лише на одному екземплярі застосунку. Масштабування кількох екземплярів із ним створить по окремому socket на кожен процес і може повертати різні локальні знімки; така топологія не підтримується. Наявний кеш endpoint може відкласти відображення змін потоку до завершення свого інтервалу (до однієї хвилини).
