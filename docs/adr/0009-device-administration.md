# ADR 0009: Адміністрування пристроїв і відкликання їхнього доступу

## Статус

Прийнято.

## Контекст

Edge Agent автентифікується через mTLS. Сервер зіставляє SHA-256 відбиток сертифіката з пристроєм і активним корпусом у PostgreSQL. До цього рішення запис пристрою створювався поза API, а адміністратор не мав штатного способу заблокувати пристрою доступ до системи.

Поточний сервер ще не має довіреного процесу видачі клієнтських сертифікатів. Реєстрація відбитка сама по собі не доводить, що сертифікат належить фізичному вузлу.

## Рішення

- Глобальний активний адміністратор може зареєструвати пристрій через `POST /api/v1/admin/devices`, передавши назву, активний корпус і 64-символьний SHA-256 відбиток уже виданого сертифіката.
- API не приймає PFX, приватний ключ, довільний CA чи сертифікатний файл і не видає сертифікати. Адміністратор спершу перевіряє підпис налаштованим клієнтським CA та належність сертифіката потрібному вузлу.
- Відбиток унікальний. Він не повертається у відповіді API й не потрапляє в payload аудиту.
- Реєстрація та `device.registered` зберігаються однією транзакцією. Відкликання через `POST /api/v1/admin/devices/{deviceId}/revoke` одночасно встановлює `RevokedAtUtc` і додає `device.revoked`.
- Зміни вимагають cookie-сесію, CSRF-токен і повторну перевірку глобальної ролі після спільного блокування мутацій доступу.
- Відкликання доступу безповоротне. Повторний запит ідемпотентно повертає первинний час; повторна реєстрація того самого відбитка заборонена.
- Відкликання доступу блокує нові mTLS-запити й команди. Активний WebSocket на поточній репліці закривається після commit. Міжреплічне миттєве закриття не гарантується; доставка в кожній репліці повторно перевіряє авторитетний стан пристрою в базі.
- API не змінює стан сертифіката у CA та не додає його до CRL/OCSP. Сертифікат може залишатися криптографічно чинним, але сервер відхиляє його відбиток після відкликання доступу пристрою.

## Наслідки

Адміністраторський запис замінює ручне редагування таблиці `devices`, але не є автоматичним pairing. До впровадження видачі сертифікатів цей маршрут можна застосовувати лише в контрольованому процесі, де походження сертифіката перевірене поза системою.

Окреме рішення потрібне для CSR, ідентифікації вузла, CA/PKI, ротації та PKI-відкликання сертифіката, а також закриття WebSocket на всіх репліках. Не додавайте ці функції через довготривалі API keys або автоматичне прийняття невідомого сертифіката.
