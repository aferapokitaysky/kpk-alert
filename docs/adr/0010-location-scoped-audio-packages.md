# ADR 0010: Пакети аудіосценаріїв для вузлів

- Статус: Accepted
- Дата: 2026-11-07

## Контекст

Edge Agent перевіряє SHA-256 точних байтів JSON-manifest, його `locationId`, код сценарію та SHA-256 WAV-файлу. Watcher поки зберігає лише глобальний hash у `sound_presets` і не має API для передачі manifest та аудіо. Через `locationId` hash пакета має бути окремим для кожної локації.

## Рішення

- Аудіофайл призначається парі «локація — сценарій». Для кожного призначення сервер видає випадковий `assetId`; ім'я, шлях і URL файла від клієнта не приймаються.
- Перша версія підтримує один PCM WAV на сценарій, розміром до 100 MiB і тривалістю до 15 хвилин — ті самі обмеження, що перевіряє Edge Agent.
- Watcher створює manifest версії 1 окремо для локації та сценарію. Його байти детерміновані; `manifestHash` у `CommandDispatch` є SHA-256 цих байтів. Manifest містить `locationId`, `presetCode`, серверне `assetId`, контрольоване ім'я `{presetCode}.wav`, hash, розмір і тривалість файла.
- Сертифікат пристрою дає доступ лише до активного сценарію, його manifest і asset тієї локації, до якої прив'язаний пристрій. API не приймає довільні шляхи чи URL.
- Незавантажені призначення тимчасово зберігають сумісність із локальними пакетами: команда отримує старий hash сценарію, а маршрут manifest повертає `404`. Після перенесення файлів адміністратор знімає публікацію сценарію, завантажує та перевіряє пакет, потім публікує його знову.
- Бінарні файли зберігаються у постійному томі Coolify, metadata — у PostgreSQL. Видалення активного опублікованого файла заборонене.

## Наслідки

- Команди однієї події можуть мати різний `manifestHash` для різних локацій.
- Завантаження не змінює опублікований сценарій на льоту; для заміни спершу знімають його публікацію.
- Перед production-використанням потрібно перевірити доступ служби до постійного тому та пройти наскрізний тест на Windows-вузлі.
