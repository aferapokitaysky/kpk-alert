# Відтворення звуку у сеансі оператора

Статус: Proposed

## Контекст

Windows-служба працює у Session 0. WASAPI в цьому сеансі може не перелічувати навушники та інші пристрої, доступні у профілі оператора. Запуск служби як інтерактивної заборонений вимогами ізоляції Windows.

## Рішення

Edge Agent залишається єдиним власником mTLS/WSS, перевірки команд, порядку sequence, дедуплікації за `commandId` і `payloadHash`, SQLite, журналу квитанцій та їх доставки. За замовчуванням аудіо відтворюється окремим процесом `Watcher.EdgeAgent.AudioWorker` після входу налаштованого інтерактивного користувача з його звичайними правами. Він не отримує мережевих облікових даних і не читає команди безпосередньо з сервера.

Служба і worker обмінюються обмеженими версіонованими повідомленнями через локальний Named Pipe. ACL дозволяє підключення лише точному SID служби; worker додатково перевіряє SID, PID, Session ID і шлях виконуваного файла клієнта. Pipe прив'язаний до активного сеансу консолі, віддалені клієнти відхиляються.

Worker повертає список активних виходів саме свого сеансу. Вибір зберігається службою у захищених даних вузла; назва пристрою не є ідентифікатором. Тест звуку та команди `start`/`stop` приймаються лише від служби. Worker не приймає довільних URL, шляхів чи параметрів оболонки: аудіофайл має бути попередньо перевірений службою за активним маніфестом та SHA-256. Worker повторно перевіряє обмеження формату, файл і endpoint перед відтворенням.

Служба фіксує `accepted` у SQLite до передачі звуку worker. Відповідь про фактичний початок або завершення має містити той самий `commandId`; квитанції створює лише служба. Якщо worker від'єднався, команда завершується помилкою і не відтворюється повторно після його перезапуску. Кожен сигнал обмежений строком дії команди й максимальною тривалістю; worker повторно перевіряє ефективний deadline перед запуском, а при заміні — до зупинки попереднього звуку.

Команди `start` і `stop` зберігають schema v1. `replace` використовує schema v2 і надсилається лише через узгоджений WebSocket subprotocol `kgta-alert.device.v2`. Кожна заміна має власний `commandId`, sequence та hash, а всі `replace` і фінальний `stop` посилаються на початковий `commandId` епізоду. Worker дедуплікує окремі команди, зупиняє поточний дочірній сигнал за episode anchor і не відновлює старий звук після reconnect.

Пряме відтворення у Session 0 залишається окремим явно налаштованим варіантом `MachineSession` (`ServiceSession`); за замовчуванням fallback вимкнений. Supervisor у сеансі користувача перезапускає завершений worker з обмеженою затримкою; новий worker не має активного звуку чи збережених команд. Автоматичного перемикання між режимами немає. У режимі користувача відсутність входу або worker переводить аудіо у стан недоступності; служба не повідомляє, що сигнал відтворюється, і не зберігає прострочені команди для пізнішого запуску. Панель має показувати цей стан і SID обраного профілю без розкриття інших профілів.

## Наслідки

- Перелік навушників і тест відтворюються у тому самому сеансі, де працює worker.
- Звук після виходу обраного користувача недоступний у режимі користувача; для цілодобового оповіщення потрібен постійно підключений аудіовузол та перевірений явний режим Session 0.
- Перевірки мають охоплювати відсутній worker, підміну pipe-сервера, інший SID/сеанс, повтор команд, від'єднання під час звуку, deadline, вихід/повторний вхід користувача та кілька одночасних сесій.
- Встановлювач реєструє запуск worker лише для заданого інтерактивного користувача й видаляє тільки власний запис під час деінсталяції.
