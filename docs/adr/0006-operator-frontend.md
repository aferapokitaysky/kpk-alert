# ADR 0006: Операторський інтерфейс як React SPA

- Статус: Accepted
- Дата: 2026-11-05

## Контекст

Watcher наразі надає ASP.NET Core API та статичні файли з `wwwroot`. Операторський пульт має кілька пов'язаних екранів, підтримує мобільне встановлення PWA та використовує сесійну автентифікацію через той самий origin. У Academica основа сторінок — Razor Layout, а React застосовується для окремих інтерактивних островів. У Watcher готового Razor Layout і спільного UI-пакета немає.

## Розглянуті варіанти

1. Razor Views із React-островами. Це найближче до структури Academica, але вимагало б додати Razor-сторінки й окремо узгодити спосіб завантаження островів для кожного екрана.
2. React SPA як статичний same-origin клієнт. Це відповідає наявному `wwwroot`, дає один типізований клієнт для пульта й аудиту та не потребує окремого runtime-сервера.

## Рішення

Обрати React SPA на TypeScript зі строгим режимом, Vite для збірки та CSS-токенами, узгодженими з Academica. Збірка розміщується у `src/Watcher.Api/wwwroot`; ASP.NET Core залишається єдиним runtime-сервером. Розробницькі інструменти React/Vite не додаються до .NET runtime-образу.

Клієнт звертається лише до наявних same-origin API. Команди надсилаються з antiforgery-токеном і `Idempotency-Key`. Service Worker зберігає лише перелік статичних ресурсів оболонки; `/api/` та запити, що змінюють стан, не перехоплюються.

## Наслідки

- Фронтенд має окремі `npm ci`, lint, typecheck, test і build-кроки в CI та Docker build.
- Немає серверного рендерингу; перший екран відображається після завантаження статичного React bundle.
- Інтерфейс не залежить від CSS або runtime Academica, але наслідує її палітру, типографіку, логотип і геометрію контролів.
- Доступність команд і аудиту остаточно перевіряє сервер; приховування навігації за ролями є лише допомогою інтерфейсу.
- Аудит використовує документовані `page`, `pageSize` та `eventType`; невідомі поля чи фільтри клієнт не вигадує.
