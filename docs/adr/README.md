# Реєстр архітектурних рішень

Архітектурне рішення (ADR) коротко фіксує контекст, варіанти, обране рішення та його наслідки. Змінювати прийняте рішення потрібно новим ADR зі станом `Superseded`, а не переписуванням історії.

Формат: `NNNN-коротка-назва.md`. Стани: `Proposed`, `Accepted`, `Rejected`, `Superseded`.

## Потрібні рішення

| №    | Тема                                                | Стан                |
| ---- | --------------------------------------------------- | ------------------- |
| 0001 | Межі Watcher та Edge Agent                          | Пропонується        |
| 0002 | Вхід із Academica через одноразовий код             | Пропонується        |
| 0003 | Джерела автоматичних тривог і правила резервування  | Потрібне погодження |
| 0004 | Підтвердження небезпечної команди та право «Відбою» | Потрібне погодження |
| 0005 | Підхід до UI та спільного бренду з Academica        | Пропонується        |
| 0006 | Операторський інтерфейс як React SPA                | Прийнято            |

До появи коду рішення зі статусом `Потрібне погодження` є відкритими вимогами, а не готовою поведінкою системи.
