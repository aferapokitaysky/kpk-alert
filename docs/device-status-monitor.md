# Моніторинг стану пристроїв

API й окремий компонент моніторингу підготовлено в `feature/device-status-monitor`.

## Підключення до навігації PWA

Щоб уникнути конфлікту з паралельними змінами `App.tsx` і спільної таблиці стилів, компонент навмисно не додано до головного маршрутизатора. Після перенесення гілки до актуального `develop`:

1. Імпортуйте `DeviceStatusPage` із `features/device-status/DeviceStatusPage`.
2. Додайте маршрут/пункт меню, доступний лише користувачам із глобальною роллю `admin` або `auditor`.
3. Залиште серверну перевірку `GET /api/v1/admin/devices` основним контролем доступу; приховування пункту меню не є авторизацією.
4. Не виводьте статус як підтвердження справності звукового обладнання.

Компонент сам завантажує дані й має стани завантаження, помилки, порожнього списку та сторінкової навігації. Він використовує наявні класи кнопок і імпортує власні адаптивні стилі.

Стан оновлюється кожні 15 секунд, доки сторінка видима. При приховуванні вкладки таймер зупиняється, а активний запит скасовується; після повернення виконується новий запит.

## Межі даних

- `isConnected` відображає лише WebSocket-з'єднання в реєстрі поточної репліки сервера.
- `lastSeenAtUtc` читається з `device_sessions` і може бути відсутнім, оскільки поточний протокол вузла не записує heartbeat.
- API не повертає UUID вузла, відбиток сертифіката або секрети.
- Екран не запускає пристрій, не змінює його стан і не дає команд.
