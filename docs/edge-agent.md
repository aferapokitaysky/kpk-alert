# Вузол оповіщення та резервна робота

## Призначення

Вузол оповіщення — Windows-служба на комп’ютері, фізично підключеному до системи гучномовців. Вона самостійно керує звуковим пристроєм і працює без відкритої панелі керування та без входу користувача у Windows.

## Локальні дані

- аудіофайли, які були опубліковані для цієї локації;
- локальна база SQLite з обробленими командами й чергою подій;
- останній перевірений знімок конфігурації;
- сертифікат пристрою та технічні налаштування з’єднання;
- журнал діагностики з обмеженим строком зберігання.

Служба запускається з мінімальними потрібними правами. `LocalSystem` використовують лише за наявності підтвердженої потреби аудіодрайвера; інакше створюють окремий обліковий запис служби.

## Обробка команди

1. Перевірити mTLS-з'єднання з Watcher, версію контракту, строк дії, локацію та `command_id`. Цілісність команди забезпечує автентифікований транспорт; хеш маніфесту окремо перевіряє локальні файли.
2. Переконатися, що сценарій дозволено, а відбитки локальних файлів збігаються з опублікованим переліком.
3. Зберегти ідентифікатор команди в SQLite до запуску звуку.
4. Застосувати погоджене правило пріоритету й за потреби зупинити попереднє відтворення.
5. Запустити файл і надіслати стан `Playing`.
6. Після завершення, зупинки або помилки зафіксувати результат. Якщо мережа недоступна, залишити подію в локальній черзі.

## Резервне отримання тривог

Резервне джерело не повинно автоматично вмикати звук лише тому, що повернуло відповідь. Для роботи потрібні погоджена політика та перевірювані правила:

1. Вузол визначає, що Watcher недоступний довше встановленого інтервалу.
2. Погоджений офіційний сервіс повертає подію для заздалегідь налаштованої території.
3. Адаптер перевіряє відповідь, формує нормалізовану подію з ідентифікатором джерела й усуває дублікати.
4. Локальна політика визначає дію, сценарій і граничну тривалість.
5. Вузол записує подію локально та передає її до Watcher після відновлення зв’язку.

Неофіційне джерело можна додати як спостереження або резерв лише після окремого погодження відповідальними особами. Воно не повинно мовчки скасовувати вже активне оповіщення.

## Локальний інтерфейс

Якщо для вузла створюється графічна панель, вона спілкується зі службою через Windows Named Pipes з ACL. Панель не отримує приватний ключ пристрою й не керує аудіопристроєм напряму.

Локальний аварійний PIN можна додати лише для обмежених погоджених дій. Він зберігається як повільний хеш із випадковою сіллю, має обмеження спроб і не дозволяє змінювати мережеві параметри чи секрети пристрою.
