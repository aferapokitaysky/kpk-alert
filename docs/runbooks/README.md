# Операційні інструкції

Це інструкції для локального та робочого середовища. Адреси, телефони чергових і секретні контакти до репозиторію не додаються.

Перед увімкненням автоматичного створення команд виконайте [процедуру перевірки й запуску](automatic-alerts.md).

Для production-розгортання в Coolify дивіться [інструкцію розгортання, міграцій і відкату](coolify-deployment.md).

## Локальна база даних

1. Скопіювати `.env.example` у `.env` та замінити пароль для локального середовища.
2. Запустити `docker compose up -d postgres`.
3. Перевірити готовність через `docker compose ps`.
4. Після завершення роботи зупинити контейнер командою `docker compose down`.

## Вузол не підключений

1. Перевірити в панелі час останнього heartbeat і стан сертифіката.
2. Перевірити живлення комп’ютера, мережу, час Windows та стан служби KGTA Alert.
3. Не позначати команду як виконану без підтвердження `Playing` від вузла.
4. Якщо сертифікат відкликаний, не обходити перевірку; провести штатне перепарування вузла.
5. Зафіксувати інцидент і його результат у журналі.

## Звук не відтворюється

1. Перевірити стан аудіопристрою та підсилювача на місці.
2. Перевірити, що сценарій дозволений для цієї локації, а відбиток файлу збігається.
3. Зберегти код помилки вузла й час UTC.
4. Не замінювати аудіофайл вручну під час активного інциденту без погодженої процедури.

## Оновлення Watcher

1. Переконатися, що резервна копія бази створена й відновлення перевірене.
2. Перевірити сумісність міграцій і попередньої версії застосунку.
3. Розгорнути зафіксовану версію, перевірити готовність API та активні підключення вузлів.
4. Виконати погоджений тест зв’язку й аудіо на тестовій локації.
5. Якщо перевірка не пройшла, повернути попередній сумісний образ і зберегти журнали.

## Відновлення з резервної копії

Відновлення виконується лише уповноваженим адміністратором у контрольованому середовищі. До повернення сервісу перевірити цілісність бази, версію схеми, ключі Data Protection, стан сертифікатів і останній ідентифікатор команди. Не відтворювати автоматично старі команди з відновленої черги.

## Перевірка стану

Стан сервісу, бази й Edge Agent показується окремо. `З’єднаний` означає наявність heartbeat, `Команду прийнято` — локальне збереження команди, `Відтворюється` — підтверджений запуск аудіо. Ці поняття не взаємозамінні.

## Підготовка входу Google

1. Створити OAuth web client у контрольованому обліковому записі Google Workspace.
2. У deployment-середовищі задати `Authentication__Google__Enabled=true`, `Authentication__Google__ClientId` та `Authentication__Google__ClientSecret`.
3. Додати callback `https://<домен>/signin-google` до дозволених URL Google OAuth.
4. Попередньо створити користувача в таблиці `users` з Google subject, призначити роль і локації в `user_roles`.
5. Переконатися, що невідомий акаунт не отримує сесію, а користувач без ролі не може створити команду.

Самореєстрація користувачів вимкнена. Віддалене створення першого адміністратора ще не автоматизоване; до появи окремої захищеної адміністративної функції початкове призначення виконується відповідальним адміністратором за погодженою процедурою бази даних.
