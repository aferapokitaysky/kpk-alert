# Розгортання, домени та середовища

## Середовища

| Середовище | Призначення | Дані |
| --- | --- | --- |
| Локальне | розробка на комп’ютері розробника | вигадані дані, локальна база |
| Тестове | перевірка інтеграцій і сценаріїв | окремі облікові записи та тестові сертифікати |
| Робоче | експлуатація закладом | захищені секрети й обмежений доступ |

Середовища не використовують спільні бази, сертифікати, cookie keys чи секрети.

## Доменна схема

Цільові назви треба підтвердити з адміністратором DNS. Як початкову схему пропонується:

| Ім’я | Призначення |
| --- | --- |
| `notify.kgta.edu.ua` | панель оператора, HTTP API та SignalR Hub |
| `journal.kgta.edu.ua` або фактичний домен Academica | система журналу та початкова точка переходу |

Для `notify` створюється DNS-запис на наявний reverse proxy. TLS-сертифікат має охоплювати точне ім’я. Не виставляти PostgreSQL назовні.

Перехід із журналу реалізується серверним обміном одноразового SSO-коду. Не задавати домен cookie `.kgta.edu.ua` і не передавати Google access token до PWA.

## Контейнери

Для розробки Docker Compose піднімає PostgreSQL, прив’язаний до loopback-інтерфейсу. Після появи застосунку додати контейнер Watcher і перевірку готовності. Edge Agent не запускається в Docker: його потрібно встановлювати як Windows-службу на фізичному вузлі біля аудіообладнання.

Робоче розгортання має містити щонайменше:

1. Reverse proxy з TLS і обмеженням заголовків.
2. Контейнер Watcher API, який слухає лише внутрішню мережу контейнерів.
3. PostgreSQL у приватній мережі з постійним томом.
4. Сховище Data Protection keys Watcher, що переживає перевипуск контейнера.
5. Окреме сховище резервних копій із шифруванням і перевіркою відновлення.

Порт бази даних не публікувати на зовнішній інтерфейс. Не зберігати production секрети в Compose-файлі чи образі контейнера.

## Конфігурація

Налаштування передаються через змінні середовища або secret store системи розгортання. `.env.example` містить тільки локальні приклади. Робочі значення ніколи не додаються в Git.

Перед запуском Watcher перевіряє наявність обов’язкових параметрів: рядка підключення до бази, шляхів/ідентифікаторів сховища ключів, параметрів SSO, зовнішнього джерела та політики вузлів. Не виводити значення секретів у повідомлення помилок.

## Перевірка перед публікацією

- зібрати та підписати контейнер із зафіксованою версією базового образу;
- застосувати сумісні міграції бази й перевірити статус здоров’я сервісу;
- перевірити TLS, callback URL, SSO та відмову в доступі неавторизованого користувача;
- перевірити підключення вузла, доставку тестової команди й отримання ACK;
- перевірити, що журнали не містять секретів;
- зафіксувати версію й мати перевірений план відновлення.

Порядок розгортання й відновлення — у [операційних інструкціях](runbooks/README.md).
