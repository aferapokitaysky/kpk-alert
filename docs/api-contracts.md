# Контракти API та доставки команд

## Загальні вимоги

- HTTP API має префікс `/api/v1`; несумісні зміни виносяться в нову версію.
- Браузерні запити, що змінюють стан, захищаються anti-forgery токеном.
- Вузли підключаються через WSS з взаємною перевіркою TLS-сертифікатів (mTLS).
- Повтор того самого запиту з тим самим `Idempotency-Key` повертає попередній результат; якщо тіло відрізняється, API повертає `409 Conflict`.
- Дата й час передаються у форматі RFC 3339 із часовим поясом UTC.

## Початкові маршрути оператора

| Метод  | Шлях                                            | Мінімальна роль                             | Призначення                                                        |
| ------ | ----------------------------------------------- | ------------------------------------------- | ------------------------------------------------------------------ |
| `GET`  | `/api/v1/locations`                             | `admin`, `notificator`                      | Доступні користувачу локації                                       |
| `GET`  | `/api/v1/presets`                               | `admin`, `notificator`                      | Опубліковані сценарії запуску                                      |
| `POST` | `/api/v1/alert-commands`                        | `notificator`                               | Створення команди запуску сценарію                                 |
| `GET`  | `/api/v1/alert-commands/{id}`                   | Ініціатор, глобальний `admin` або `auditor` | Перегляд команди та її цілей                                       |
| `GET`  | `/api/v1/alert-commands/{commandId}/deliveries` | Ініціатор, глобальний `admin` або `auditor` | Посторінковий перегляд доставок команди                            |
| `GET`  | `/api/v1/audit-events`                          | `auditor`                                   | Перегляд журналу дій                                               |
| `GET`  | `/api/v1/alert-sources/status`                  | Публічний, лише читання                     | Зовнішні статуси області, району й громади з джерелами та свіжістю |

Маршрути входу: `GET /api/v1/auth/login` (перехід до Google OAuth), `GET /api/v1/auth/csrf-token` (видача парного request token і cookie), `GET /api/v1/auth/session` (поточний стан сесії, глобальні ролі та можливості UI) і `POST /api/v1/auth/logout` (завершення локальної сесії). Session endpoint повертає лише `authenticated`, allowlist глобальних ролей та `capabilities.canOperate` / `capabilities.canViewAudit`; він не розкриває email, Google subject, токени чи локальні призначення. Локальні ролі дають змогу відкрити пульт, але не надають глобального доступу до журналу аудиту. Backend окремо перевіряє права для кожної локації та endpoint аудиту. Для logout та створення команди браузер передає request token у заголовку `X-CSRF-TOKEN`; cookie `__Host-KgtaAlert.AntiForgery` має прапорці Secure, HttpOnly і SameSite=Strict. Google OAuth увімкнений лише за наявності `Authentication:Google:Enabled`, Client ID та Client Secret. Увійти можуть лише активні користувачі, яких адміністратор попередньо зареєстрував у базі за зовнішнім Google subject.

`GET /api/v1/locations` повертає лише активні корпуси, доступні ролі користувача. Глобальний адміністратор або оператор бачить усі активні корпуси; локальне призначення ролі відкриває лише закріплені корпуси.

`GET /api/v1/presets` повертає лише опубліковані сценарії для адміністратора або оператора з глобальною чи локальною роллю. Пульт будує кнопки з цієї відповіді; неопубліковані або відсутні в базі сценарії не відображаються. Endpoint наразі підтримує лише запуск звукового сценарію, а окрема дія «Відбій» потребує власного контракту та прив’язки до активної події.

`GET /api/v1/audit-events` доступний користувачам із глобальною роллю `auditor` або `admin`. Параметри `page` (від 1, типово 1) та `pageSize` (1–100, типово 50) керують посторінковою видачею; `eventType` необов’язково залишає події одного точного типу. Відповідь містить `items`, `page`, `pageSize` і `totalCount`. Кожна подія повертає ID, тип, тип і ID актора, час UTC та JSON-поле `payload`. Події впорядковані від нових до старих; за однакового часу порядок задає ID. API не приймає довільний SQL-фільтр і не повертає email, зовнішній subject, IP-адреси чи токени.

`GET /api/v1/alert-sources/status` повертає інформаційні спостереження від alerts.in.ua і NEPTUN окремо для Полтавської області, Кременчуцького району й Кременчуцької громади. Endpoint не вимагає сесії, не запускає команд і не передає браузеру токен джерела. alerts.in.ua має точні UID області `19` і громади `1088`; код `N` консервативно відображається як `unknown`, бо документація endpoint описує його як відсутність інформації. NEPTUN надає область і район; адаптер зіставляє записи за стабільними ключами `poltavska` та `poltavska:kremenchutskyi`, а районний статус не використовується як статус громади. Ключ є основним ідентифікатором, тому зміна підпису не змінює відповідний статус; знайома назва з неочікуваним ключем сигналізує невідомий контракт. Дубльований ключ або запис некоректного формату дає `unknown`, а не підтверджену відсутність тривоги. Час `since` у NEPTUN означає початок події, тому його не передають як час оновлення даних. Поле `level` може бути `active`, `inactive`, `partial`, `unknown` або `conflict`; `freshness` — `fresh`, `stale` або `unknown`. Для автоматизованого споживача `authoritativeObservation` вказує вибране актуальне спостереження, а перелік `observations` зберігає окремі відповіді джерел. Червоний і жовтий рівні передаються лише коли їх повідомило джерело. Помилка, обмеження частоти чи застаріла відповідь не означають відсутність тривоги; неочікуваний виняток одного провайдера лишає його стан невідомим і не перериває відповідь іншого. Токен alerts.in.ua налаштовується тільки на сервері через `ALERTS_IN_UA_TOKEN` або `AlertSources:AlertsInUa:Token`; його не можна записувати до репозиторію чи журналу. Кожна картка інтерфейсу містить посилання на джерело.

API для створення й публікації сценаріїв ще немає. Поки адміністрування не реалізоване, чисте розгортання не містить доступних сценаріїв і пульт це явно показує.

`POST /api/v1/alert-commands` наразі приймає лише дію `start`; розмір тіла запиту не має перевищувати 16 KiB. Потрібні 1–50 унікальних активних `locationIds`, опублікований `presetCode` із SHA-256 manifest hash у форматі 64 шістнадцяткових символів та UUID у заголовку `Idempotency-Key`. Перевірка формату hash не доводить, що аудіофайл наявний на вузлі. Повторне використання ключа тим самим користувачем дозволене лише з тією самою дією, сценарієм і набором корпусів; порядок корпусів не має значення. Інше тіло для зайнятого ключа повертає `409 Conflict`. Команда, цілі, аудит і подія outbox зберігаються в одній транзакції. `expiresAtUtc` є обов’язковим полем команди: для операторської команди це п’ять хвилин від створення, для хвилини мовчання — рівно 09:01 `Europe/Kyiv` у день запуску. Майбутній споживач доставки й вузол зобов’язані відхиляти команду за `now >= expiresAtUtc` до початку відтворення. `InitiatedByUserId` є порожнім лише для системної команди; її перегляд дозволений глобальним адміністраторам і аудиторам. Наразі endpoint лише записує команду в outbox, а підтвердження `202 Accepted` означає `Queued`, не фактичне відтворення; стан `Playing` або `Completed` має надходити від вузла після реалізації його інтеграції.

`GET /api/v1/alert-commands/{id}` повертає команду її ініціатору або користувачу з глобальною роллю `admin` чи `auditor`. Невідома команда й команда без прав для поточного користувача мають однакову відповідь `404`, щоб не розкривати існування запису; endpoint встановлює `Cache-Control: no-store`.

`GET /api/v1/alert-commands/{commandId}/deliveries` повертає сторінку доставок конкретної команди. Доступ мають її ініціатор або користувач із глобальною роллю `admin` чи `auditor`; системні команди без ініціатора доступні лише цим глобальним ролям. `page` нумерується від 1 і типово дорівнює 1; `pageSize` типово дорівнює 50 та має бути в межах 1–100. Відповідь містить `items`, `page`, `pageSize` і `totalCount`; елементи стабільно впорядковані за `deviceId`. Дані елемента: `deviceId`, `deviceName`, `state`, `createdAtUtc`, `expiresAtUtc`, `lastAttemptAtUtc` та `attemptCount`. Відомості сертифіката пристрою не повертаються. Невідома команда й команда без прав для поточного користувача мають однакову відповідь `404`, щоб не розкривати існування запису; endpoint встановлює `Cache-Control: no-store`.

Під час створення сервер атомарно призначає кожній цілі `sequence`, який зростає окремо в межах кожної локації. Для багатолокаційної команди лічильники блокуються у стабільному порядку UUID; команда, її номери й outbox фіксуються разом. Номери не повторюються після успішного commit, а пропуски допустимі після скасованої транзакції або історичного backfill. Порядок задає сервер, клієнт не передає і не змінює `sequence`.

`GET /api/v1/audit-events` доступний у поточній версії API. Інші маршрути таблиці, для яких реалізацію не описано вище, залишаються цільовими.

Приклад запиту:

```json
{
  "action": "start",
  "presetCode": "evacuation",
  "locationIds": ["9ab5d623-80d7-48c3-99be-cbebdd9a535a"],
  "reason": "Погоджена навчальна перевірка"
}
```

Клієнт не передає URL аудіо, шлях до файлу, рівень пріоритету чи особу ініціатора. Сервер бере ініціатора із сесії, а допустимі параметри — з опублікованого сценарію.

Відповідь `202 Accepted` означає, що команду записано й поставлено на доставку. Вона не є підтвердженням відтворення звуку; це підтверджують лише події стану від вузла.

## Події між Watcher і вузлом

DTO та назви подій визначаються в `Watcher.Contracts`; клієнти не дублюють їх як довільні рядки.

| Напрямок        | Подія                    | Обов’язкові дані                                                                                                                                                                                                          |
| --------------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Watcher → вузол | `CommandDispatch`        | `schemaVersion`, `commandId`, `deviceId`, `locationId`, `sequence`, `action`, `issuedAtUtc`, `expiresAtUtc`; для `start` також `presetCode`, `manifestHash`, `maxPlaybackDurationSeconds`; для `stop` — `targetCommandId` |
| Вузол → Watcher | `CommandReceipt`         | `schemaVersion`, `eventId`, `commandId`, `sequence`, `state`, `occurredAtUtc`, код причини для відмови                                                                                                                    |
| Вузол → Watcher | `Heartbeat`              | `deviceId`, `sentAtUtc`, `audioState`, `configVersion`                                                                                                                                                                    |
| Watcher → вузол | `ConfigurationAvailable` | `version`, адреса переліку файлів, підпис                                                                                                                                                                                 |

Допустимі стани підтвердження: `Accepted`, `Playing`, `Completed`, `Stopped`, `Rejected`, `Failed`, `Expired`. Для `Rejected`, `Failed` і `Expired` потрібен код причини. Технічні подробиці не показуються кінцевому користувачу.

## Дедуплікація й порядок

1. Watcher створює команду, цілі локацій, запис аудиту й подію outbox в одній транзакції.
2. Вузол атомарно зберігає `command_id` у SQLite перед початком відтворення.
3. Повторно отримана команда повертає раніше збережений стан і не запускає звук знову.
4. `sequence` задає порядок у межах локації; UUID для цього не використовують.
5. Прострочена команда відхиляється і споживачем outbox, і вузлом до відтворення: перевірка виконується за `now >= expiresAtUtc`. Допустиме відхилення годин вузла задається окремо.

## Формат помилки

API повертає помилки у форматі Problem Details із кодом HTTP і `traceId`. Відповідь не містить стеку викликів, секретів, відбитків сертифікатів або подробиць мережі.
