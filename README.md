# KGTA Alert

Система екстреного оповіщення та повсякденного аудіоінформування Кременчуцького коледжу. Репозиторій містить центральний API Watcher, операторський вебінтерфейс і проєктні матеріали автономного вузла Edge Agent.

> Стан вузлів і фактичне відтворення звуку ще не надходять від Edge Agent. Пульт показує прийняття команди сервером окремо від підтвердження обладнання.

## Призначення

- запускати дозволені сигнали з панелі оператора й отримувати підтвердження відтворення в кожному корпусі;
- продовжувати локальне відтворення за відсутності центрального сервера;
- підтримувати кілька корпусів і адресне надсилання команд;
- вести перевірюваний журнал дій і стану обладнання;
- інтегруватися з Academica через окремий захищений вхід.

## Склад проєкту

| Компонент    | Призначення                                      | Технології                           |
| ------------ | ------------------------------------------------ | ------------------------------------ |
| Watcher API  | сесії, ролі, корпуси, сценарії, команди й аудит  | ASP.NET Core 10, PostgreSQL          |
| Operator PWA | адаптивний пульт і перегляд журналу дій          | React 19, TypeScript, Vite           |
| Edge Agent   | майбутній локальний запуск аудіо й підтвердження | .NET Worker Service, Windows, SQLite |
| PostgreSQL   | облікові записи, конфігурація, команди й аудит   | PostgreSQL 16                        |

## Запуск локальної бази даних

Потрібен Docker Desktop або сумісний Docker Engine із Compose v2.

```bash
cp .env.example .env
docker compose up -d postgres
docker compose ps
```

PostgreSQL буде доступний лише локально на `127.0.0.1:${POSTGRES_PORT}`. Дані доступу з `.env` призначені тільки для розробки.

```bash
docker compose down
```

## Перевірки та запуск інтерфейсу

Для локальної роботи потрібні Node.js 24 і .NET SDK 10. Команди фронтенду виконуються з кореня репозиторію:

```bash
npm ci
npm run lint
npm run typecheck
npm test
npm run build
```

Щоб працювати через Vite, запустіть Watcher на `https://localhost:5001`, а потім `npm run dev`. Для іншого URL API задайте `VITE_API_PROXY`. Google-вхід потребує налаштованого OAuth клієнта й доступного тестового облікового запису. Контейнер збирає клієнтські файли окремим Node.js етапом; у runtime-контейнері працює лише ASP.NET Core.

## Поточний стан і наступні кроки

API, сесійний вхід, журнал аудиту й операторський пульт реалізуються в цьому репозиторії. Підключення вузлів, підтвердження відтворення та автономна робота потребують окремого Edge Agent. Автоматичне отримання й запуск сигналів не ввімкнені; джерела та правила для них мають бути окремо погоджені.

## Рішення, які потрібно погодити

До реалізації автоматичних тривог треба погодити надійні джерела, події для автоматичного запуску й осіб, які можуть дати відбій. Перелік рішень — у [реєстрі ADR](docs/adr/README.md).

## Доступ до репозиторію

Репозиторій призначений для внутрішнього використання KGTA. Не додавайте до нього справжні ключі, сертифікати, IP-адреси інфраструктури чи персональні дані.
