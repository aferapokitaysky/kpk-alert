# KGTA Alert

Система екстреного оповіщення та повсякденного аудіоінформування Кременчуцького коледжу. Репозиторій містить центральний API Watcher, операторський вебінтерфейс і Windows-службу Edge Agent.

> Пульт розрізняє прийняття команди сервером, її доставку вузлу та підтвердження відтворення. Автоматичне оповіщення про тривогу вимкнене за замовчуванням і потребує налаштованих джерел, сценарію та перевірки обладнання.

## Призначення

- запускати дозволені сигнали з панелі оператора й отримувати підтвердження відтворення в кожному корпусі;
- продовжувати локальне відтворення за відсутності центрального сервера;
- підтримувати кілька корпусів і адресне надсилання команд;
- вести перевірюваний журнал дій і стану обладнання;
- надавати доступ попередньо зареєстрованим користувачам через Google OAuth і власні ролі Watcher.

## Склад проєкту

| Компонент    | Призначення                                       | Технології                   |
| ------------ | ------------------------------------------------- | ---------------------------- |
| Watcher API  | сесії, ролі, корпуси, сценарії, команди й аудит   | ASP.NET Core 10, PostgreSQL  |
| Operator PWA | адаптивний пульт і перегляд журналу дій           | React 19, TypeScript, Vite   |
| Edge Agent   | локальне відтворення, стан і підтвердження команд | .NET Windows Service, SQLite |
| PostgreSQL   | облікові записи, конфігурація, команди й аудит    | PostgreSQL 16                |

## Запуск локальної бази даних

Потрібен Docker Desktop або сумісний Docker Engine із Compose v2.

```bash
cp .env.example .env
docker compose up -d postgres
docker compose ps
```

PostgreSQL буде доступний лише локально на `127.0.0.1:${POSTGRES_PORT}`. Дані доступу з `.env` призначені тільки для розробки.

```bash
docker compose down
```

## Перевірки та запуск інтерфейсу

Для локальної роботи потрібні Node.js 24 і .NET SDK 10. Команди фронтенду виконуються з кореня репозиторію:

```bash
npm ci
npm run lint
npm run typecheck
npm test
npm run build
```

Щоб працювати через Vite, запустіть Watcher на `https://localhost:5001`, а потім `npm run dev`. Для іншого URL API задайте `VITE_API_PROXY`. Google-вхід потребує налаштованого OAuth клієнта й доступного тестового облікового запису. Контейнер збирає клієнтські файли окремим Node.js етапом; у runtime-контейнері працює лише ASP.NET Core.

## Поточний стан і наступні кроки

У репозиторії реалізовано API, сесійний вхід, журнал аудиту, операторський пульт, транспорт команд через WebSocket із mTLS та Windows-службу Edge Agent. Сервер приймає квитанції вузлів і показує стан доставок. Джерела тривог та правила автоматичного запуску реалізовані, але автоматичне надсилання команд вимкнене за замовчуванням. Розклад хвилини мовчання працює за часом `Europe/Kyiv`; для відтворення потрібні опублікований сценарій і перевірений аудіофайл на вузлах.

## Рішення, які потрібно погодити

Перед увімкненням автоматичного оповіщення заклад має затвердити сценарій, відповідальних операторів, порядок відбою та перевірити доставку й відтворення на обладнанні кожного корпусу. Перелік архітектурних рішень — у [реєстрі ADR](docs/adr/README.md).

## Доступ до репозиторію

Репозиторій призначений для внутрішнього використання KGTA. Не додавайте до нього справжні ключі, сертифікати, IP-адреси інфраструктури чи персональні дані.
