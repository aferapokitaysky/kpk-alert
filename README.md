# KGTA Alert

Система екстреного оповіщення та повсякденного аудіоінформування Кременчуцького коледжу. Проєкт складається з центрального сервера керування (Watcher) та автономних вузлів оповіщення в корпусах (Edge Agent).

> Проєкт на етапі проєктування. Документація описує цільову архітектуру; прикладні сервіси буде додано після погодження першої версії.

## Призначення

- запускати дозволені сигнали з панелі оператора й отримувати підтвердження відтворення в кожному корпусі;
- продовжувати локальне відтворення за відсутності центрального сервера;
- підтримувати кілька корпусів і адресне надсилання команд;
- вести перевірюваний журнал дій і стану обладнання;
- інтегруватися з Academica через окремий захищений вхід.

## Состав проекта

| Компонент | Призначення | Технології |
| --- | --- | --- |
| Watcher API | команды, роли, аудит, конфигурация, статусы | ASP.NET Core 8+, PostgreSQL, SignalR |
| Operator PWA | швидкий запуск дозволених сценаріїв | React або Razor; рішення буде зафіксовано в ADR |
| Edge Agent | локальное аудиовоспроизведение, кэш, ACK, fallback | .NET Worker Service, Windows, SQLite |
| PostgreSQL | данные сервера, аудит, конфигурация | PostgreSQL 16 |

## Запуск локальної бази даних

Потрібен Docker Desktop або сумісний Docker Engine із Compose v2.

```bash
cp .env.example .env
docker compose up -d postgres
docker compose ps
```

PostgreSQL буде доступний лише локально на `127.0.0.1:${POSTGRES_PORT}`. Дані доступу з `.env` призначені тільки для розробки.

```bash
docker compose down
```

## Черговість розробки

1. Watcher: користувачі, ролі, локації, сценарії та журнал аудиту.
2. Вузол оповіщення: безпечне з’єднання, локальні файли, підтвердження й heartbeat.
3. Панель оператора: запуск і зупинка сценаріїв із захистом від випадкового натискання.
4. Моніторинг стану й перевірка відмов.
5. Інтеграція офіційного джерела після погодження правил автоматичного запуску.

## Рішення, які потрібно погодити

До реалізації автоматичних тривог треба погодити надійні джерела, події для автоматичного запуску й осіб, які можуть дати відбій. Перелік рішень — у [реєстрі ADR](docs/adr/README.md).

## Доступ до репозиторію

Репозиторій призначений для внутрішнього використання KGTA. Не додавайте до нього справжні ключі, сертифікати, IP-адреси інфраструктури чи персональні дані.
